IndQuestResults — Open-Source Result<T> Library for .NET

Open Source .NET 10 NuGet Functional Programming 2025–2026

Designed, built and published IndQuestResults — a zero-dependency, functional Result<T> error-handling library for .NET — released under Exxerpro on NuGet.org through a fully automated release pipeline. Sole author and maintainer, from initial design through every published release.

Scope of Work

  • Designed a unified Result<T> API — Map/Bind/Match/Recover, async support via ResultAsync, collection-traversal helpers, and a reactive/Observable bridge — with zero runtime dependencies.
  • Shipped a companion Roslyn analyzer with an automated code-fix to guide correct usage at compile time.
  • Built and maintain the release pipeline: tag-triggered GitHub Actions publishing straight to NuGet.org via OIDC Trusted Publishing.
  • Audited the reactive-extension layer for exception-handling correctness, found a case where stream errors were silently converted into false successes, and shipped the fix.

Architecture

Built around railway-oriented programming — chaining operations so failures short-circuit predictably instead of relying on exceptions for control flow. Delivered as one unified package (core, async, collection, functional and reactive extensions together) rather than fragmented sub-packages, kept dependency-free by design, and mutation-tested and coverage-tracked as part of the CI process.

  • .NET 9 / 10, C#
  • xUnit v3, Stryker mutation testing
  • Roslyn analyzers & code fixes
